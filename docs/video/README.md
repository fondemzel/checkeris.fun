# Съёмка роликов Чекера

Как снимать короткие вертикальные ролики об интерфейсе: гладко, 60 кадров в секунду, с выделением того, о чём говорит голос. Рецепт выверен на ролике 1 «Куда уходят деньги» (октябрь 2026). Ниже — подготовка, съёмка, правила режиссуры и грабли, на которые уже наступили.

## Как это устроено

- **Сценарий** — файл `NN-тема.film.mjs` рядом с текстом ролика `NN-тема.md`. В нём действия по секундам: «на 3,2 с выделить „Питание“, на 4,4 с нажать». Темп задаёт озвучка, а не скорость телефона.
- **Исполнитель** — [scripts/film.mjs](../../scripts/film.mjs). Ведёт страницу Чекера через отладку Chrome: касания, свайпы, долгие нажатия, набор текста, выделение. Пишет экран.
- **Выделение** — `film` в [site/m/app.js](../../site/m/app.js). Затемняет всё вокруг элемента. Людям не видно: без вызова из сценария ничего не создаётся.
- **Где снимаем** — Chrome на настоящем телефоне, во весь экран. Пишет scrcpy: видео кодирует сам телефон, аппаратно, кадры не теряются.

## Подготовка (один раз)

**На компьютере:**

1. adb — уже есть в Android SDK: `C:/Users/fondemzel/AppData/Local/Android/Sdk/platform-tools/adb.exe`.
2. scrcpy — скачать архив для Windows с [github.com/Genymobile/scrcpy/releases](https://github.com/Genymobile/scrcpy/releases) и распаковать. Путь к `scrcpy.exe` — в переменную `SCRCPY`.
3. ffmpeg — `pip install imageio-ffmpeg`. Скрипт найдёт его сам (или путь в переменной `FFMPEG`).
4. Node 24 — для скрипта.

**На телефоне:**

1. Включена отладка по USB, телефон подключён и разрешил этот компьютер.
2. Установлен Chrome. Язык Chrome неважен: скрипт сам включает в Чекере русский.
3. Экран разблокирован и не гаснет во время съёмки.

**Учётная запись для съёмки.** Отдельная, `__video__`, в демо-режиме (семья с ребёнком, отпуском и Новым годом). Свой аккаунт не трогаем: входим ею в Chrome телефона, а не в приложение Чекер, поэтому приложение и его синхронизация банков не затрагиваются. Токен для входа выдаёт сервер:

```bash
cat > /tmp/film-token.mjs <<'EOF'
import { DatabaseSync } from 'node:sqlite';
import { issueToken } from '/opt/checker/api/src/auth.mjs';
const db = new DatabaseSync('/opt/checker/api/data/checker.db');
db.exec('PRAGMA busy_timeout = 5000');
const user = db.prepare("SELECT id FROM users WHERE login = '__video__'").get();
db.prepare("DELETE FROM tokens WHERE user_id = ? AND label = 'film'").run(user.id);
console.log(issueToken(db, user.id, 'film').token);
EOF
scp /tmp/film-token.mjs vps2:/tmp/ && ssh vps2 "cd /opt/checker/api && node /tmp/film-token.mjs; rm /tmp/film-token.mjs"
```

Токен — пропуск в учётную запись: в репозиторий и в сценарии его не класть, передавать в команде (`--token`) или в переменной `FILM_TOKEN`.

## Съёмка

```bash
export FILM_DEVICE=75kb9d4hqsqs9hdq   # номер телефона в `adb devices`
export SCRCPY=…/scrcpy.exe
node scripts/film.mjs run docs/video/01-expenses.film.mjs --phone --token <токен> \
  --today 2026-12-18 --theme dark --pace 2 --rec video/01-expenses/raw/дубль.mp4
```

- `--phone` — Chrome на телефоне: открыть Чекер, войти, развернуть во весь экран.
- `--today 2026-12-18` — «сегодня» для страницы на время съёмки. Демо расписано до 31 декабря; с подменой нужный месяц — текущий, и лимит показывает «можно в день», а не «период ещё не начался».
- `--theme dark` — тёмная тема: ролики снимаем в ней.
- `--pace 2` — всё вдвое медленнее: анимации приложения, выделение, жесты и отметки сценария. Ролик выходит вдвое длиннее отметок в сценарии (40 с → ~76 с).
- `--rec` — записать. Без него сценарий просто прогоняется: так удобно проверять его перед записью.

Что происходит: Chrome открывает Чекер, скрипт входит, включает русский, прячет плашку «демо-режим», включает подсказку при свайпе (она показывает, куда листают), разворачивает страницу во весь экран и ждёт ~11 с, пока уйдёт подсказка Chrome о полноэкранном режиме. Потом стартует scrcpy, идёт сценарий. scrcpy останавливается по пределу времени; скрипт ждёт его и режет запись ровно по сценарию: MP4, H.264, 60 к/с, 1080×2400.

Отладка шагов: `node scripts/film.mjs eval "<js>" --phone` выполняет выражение на странице (Chrome при этом заново открывает Чекер).

## Сценарий: команды

Сценарий — модуль `export default async (f) => { … }`. Цель — CSS-селектор, `'text:Питание'` (видимый элемент с этим текстом) или координаты `{ x, y }` в пикселях страницы.

| Команда | Что делает |
|---|---|
| `f.at(сек)` | ждать отметки времени ролика. Если шаг опоздал больше чем на 0,15 с — пишет в консоль |
| `f.wait(мс)` | пауза |
| `f.until('js', мс)` | ждать, пока выражение на странице станет верным (экран открылся, период сменился) |
| `f.tap(цель)` | нажатие |
| `f.swipe(откуда, { dx, dy }, мс)` | свайп смахиванием: палец разгоняется и отрывается на ходу |
| `f.down(цель)`, `f.move(цель, мс)`, `f.up()` | палец по частям — для долгого нажатия с ведением по попапу |
| `f.type('текст', { every })` | набор по букве |
| `f.hideKeyboard()` | убрать экранную клавиатуру |
| `f.spot(цель, { pad, up, dim })` | выделить. `up: '.card'` — подняться от найденного текста до всего блока |
| `f.clear()` | снять выделение (растворением) |
| `f.eval('js')` | выполнить на странице |
| `f.eval("film.tab('summary', { mode: 'ring', from, to })")` | перейти на вкладку без перезагрузки страницы |

Удобный приём — выделять «на опережение», как только элемент появился в разметке (см. `spotSoon` в [01-expenses.film.mjs](01-expenses.film.mjs)).

## Правила режиссуры

**Стратегия (с 22.10.2026, ролик 0).** Снимаем только ключевые экраны и анимации — без пауз «под голос»: сцены растягиваются на монтаже. Перед каждым нажатием выделение сначала ложится туда, куда нажмём (такт ~0,45 с), важное на экране тоже сначала выделяется. Сценарий идёт подряд, ждёт только конца анимаций (помощники `show`, `press`, `pressTab` — в [00-overview.film.mjs](00-overview.film.mjs)). Отметки `f.at` — для роликов, снятых под готовую озвучку, как ролик 1.

`f.spot` принимает и список целей — один вырез вокруг всех (две кнопки рядом).

1. **Выделение никогда не появляется внезапно.** Появление — «наезд»: вырез сжимается к элементу от краёв экрана, затемнение проступает. Это делает само `film.spot`.
2. **Уход — растворением.** Вырез остаётся на месте, затемнение плавно гаснет (`f.clear()`). Не расширять вырез к краям.
3. **Выделение приходит заранее.** Ставить его, как только элемент появился (экран ещё выезжает, лента ещё листается). Рамка едет вместе с элементом и к его остановке уже на месте. Попап выделять сразу после нажатия — рамка растёт вместе с ним.
4. **Выделять блок целиком**, а не текст: строку покупки (`up: '.row'`), карточку (`up: '.card'`), всё поле поиска (`label.search`).
5. **Исчез элемент — выделение уходит.** Это автоматически: держать рамку на пустом месте нельзя.
6. **Свайпы — смахиванием.** Палец не тормозит перед отрывом, иначе экран «сдвигается, замирает, появляется новый».
7. **Без резких смен экрана.** Например, два «назад» подряд резко переключали кольца — лучше вернуться один раз и продолжать там.
8. **Один кадр — одна мысль.** Пока голос говорит о поиске, на экране только поиск.
9. **В кадре нет служебного:** плашки демо-режима и подсказки Chrome. Скрипт прячет их сам. Подсказка при свайпе — не служебное: она показывает, куда листают, и остаётся.
10. **Тёмная тема** (`--theme dark`).
11. **Касания видны.** Скрипт сам рисует отметку под пальцем (`film.touch` в приложении): небольшой светлый круг под пальцем, едет за ним, при отпускании гаснет. Без колец и следа. Системное «показывать касания» не подходит: касания приходят из скрипта, и Android их не рисует.

## Грабли (и почему сделано так)

| Что было | Причина | Как решено |
|---|---|---|
| Эмулятор Android: запись 10–14 к/с | `screenrecord` внутри эмулятора кодирует программно | Не снимать в эмуляторе. Запись средствами эмулятора (`adb emu screenrecord`) даёт ~45 к/с и подвисания — тоже хуже телефона |
| Chrome на компьютере не управляется | Политика Windows `RemoteDebuggingAllowed = 0` у Chrome и Edge | Не трогать политику. Chrome for Testing работает, но запись кадров браузера (screencast) даёт только ~33 к/с |
| Выделение тормозило отрисовку (46 к/с вместо 60) | Огромная тень, меняя размер, перерисовывала весь экран каждый кадр | Затемнение из восьми кусков, которые только сдвигаются и масштабируются ([app.js](../../site/m/app.js), `film.draw`) |
| Свайп под нагрузкой растягивался с 0,36 до 1,4 с | Каждый шаг пальца ждал ответа страницы | Шаги пальца идут по часам, ответ не ждём |
| «Сдвинулся — замер — появился новый» при листании | Палец тормозил перед отрывом | Свайп смахиванием (`flick` в `glide`) |
| Пауза перед новым экраном при `--pace` | Замедлялись и таймеры страницы, а новый экран встаёт в ленту по таймеру | Замедляются только часы анимаций и сами анимации, таймеры — нет |
| В Chrome на телефоне нажатия не срабатывали | Из голых касаний (`dispatchTouchEvent`) Chrome не собирает «клик» | Нажатие — жестом целиком: `Input.synthesizeTapGesture` |
| Служебное касание открыло «Выключить демо-режим?» | Попало в плашку под заголовком | Касание — в пустое поле у края, и его клик гасится |
| Подсказка Chrome о полноэкранном режиме в первых секундах | Держится ~9 с | Ждать 11 с перед записью |
| Перезагрузка страницы выходит из полноэкранного режима | Так устроен браузер | Переходы в сценарии — `film.tab(…)`, без перезагрузки |
| Надписи по-английски | Chrome телефона на английском | Скрипт ставит `checker.lang = ru` |
| Не найти вкладку по отладке сразу после запуска Chrome | Отладка отвечает не сразу; адрес в списке без порта | Повторы; адрес собирается с проброшенным портом |
| «Каркассон» пять раз за год в демо | Генератор не помнил разовые покупки | Список разовых вещей (`ONCE` в [api/src/demo.mjs](../../api/src/demo.mjs)) |

## Новый ролик: порядок

1. Текст и раскадровка — `NN-тема.md`: зачем человеку (первая фраза — польза), действия по секундам, текст диктора, подписи.
2. Сценарий — `NN-тема.film.mjs`: отметки под фразы, выделение на опережение.
3. Прогон без записи: смотреть, нет ли «опоздание к N с» и «не дождались».
4. Запись с `--rec`, проверка по кадрам.
5. Голос — синтез речи (текст с разметкой — `NN-тема.voice.md`), отдельный файл на каждую фразу, в `video/NN-тема/voice/`. Монтаж, подрезка длины, ускорение и сведение — в After Effects.
