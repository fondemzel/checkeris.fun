# Бизнес

Работа с пользователями: админка, регистрация и вход, тарифы и ограничения, поддержка, воронка от первого знакомства до постоянного использования.

## Границы

**Сюда:** админка (пользователи, бюджеты, активность, ошибки), регистрация и вход (пароль, Telegram, ключи доступа), тарифы и квоты (сканы, банки, участники), оплата, поддержка (бот, обращения), воронка и метрики (демо-режим → регистрация → первый чек/банк → удержание), приглашения в бюджет, рассылки бота.

**Не сюда:** экраны приложения (→ [app](../app/README.md)), банки (→ [banks](../banks/README.md)), ролики и публикации (→ [video](../video/README.md)).

## Код

| Путь | Что |
|---|---|
| `api/src/auth.mjs`, `users.mjs` | вход, токены, пользователи |
| `api/src/budgets.mjs`, `members.mjs` | бюджеты, участники, приглашения, уведомления участникам |
| `api/src/quota.mjs` | суточные квоты сканов — готовая точка для тарифов |
| `api/src/telegram.mjs`, `bot/relay.mjs` | Telegram-бот: вход, уведомления — естественный канал поддержки |
| `api/src/demo.mjs` | демо-режим — «посмотреть до регистрации», начало воронки |
| `site/cabinet/` | кабинет на компьютере — место для админки |
| `api/db/schema.sql` | таблицы `users`, `budgets`, `tokens` и др. |

## Документы

- [passkeys.md](passkeys.md) — вход по отпечатку (ключи доступа), отложено до сторонних пользователей.
- Кабинет и доступ — [../app/cabinet.md](../app/cabinet.md).

## Важное

- Банковские данные людей в админке не показывать (сессии, операции) — только служебное: подключён ли банк, когда синхронизировался, ошибки.
- Никаких личных правил одного пользователя в общем коде.

## Начало сессии

> Это сессия «Бизнес»: админка, пользователи, тарифы, поддержка, воронка (границы — docs/business/README.md). Сначала изучи docs/business/README.md, пользователей и бюджеты в схеме и коде, квоты, бота, демо-режим. Предложи план по шагам с карточками на доске в разделе «Бизнес» — без кода.
