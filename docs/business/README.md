# Бизнес

Работа с пользователями: админка, регистрация и вход, тарифы и ограничения, поддержка, воронка от первого знакомства до постоянного использования.

## Границы

**Сюда:** админка (пользователи, бюджеты, активность, ошибки), регистрация и вход (пароль, Telegram, ключи доступа), тарифы и квоты (сканы, банки, участники), оплата, поддержка (бот, обращения), воронка и метрики (демо-режим → регистрация → первый чек/банк → удержание), приглашения в бюджет, рассылки бота.

**Не сюда:** экраны приложения (→ [app](../app/README.md)), банки (→ [banks](../banks/README.md)), ролики и публикации (→ [video](../video/README.md)).

| `api/src/admin.mjs`, `site/admin/` | админка (`/admin/`, только `role = admin`) — центр управления для компьютера по образцу настроек GitHub: меню слева, разделы в `#/…` (обзор, люди и страница человека, каналы прихода, нагрузка, подключения, ошибки). С кабинетом не связана: свой вход (Telegram с `client = admin` — пускает только администратора и аккаунтов не заводит; запасной — пароль), свой токен (`checker.admin-token`), ссылок между ними нет |

| `site/cabinet/` | кабинет на компьютере |
| `api/db/schema.sql` | таблицы `users`, `budgets`, `tokens` и др. |

## Админка

- **Откуда пришли** — метка ссылки `checkeris.fun/?from=<метка>` (заводится в админке, там же копируется ссылка), приглашение в бюджет (вступил в первые сутки) или «напрямую». Запоминается первая метка; сохраняется при регистрации через Telegram.
- **Активность** — отметка «был сегодня» в `usage_daily` (`kind = 'active'`), её ставит любой запрос с токеном. Пишется с 0.61.0, раньше истории нет.
- В подсчётах нет служебных пользователей демо-режима (`__…`) и администратора.
- Пока не решено: метка для ссылки прямо на бота (`start=` занят кодом входа) и для Android-приложения, установленного из APK.

## Поддержка

- Человек пишет боту: всё, что не вход, — обращение. Пишет человек без аккаунта — тоже обращение, автоответ подсказывает, как войти.
- В приложении — «Настройки → Помощь → Поддержка»: свои обращения списком (с числом непрочитанных ответов), «Новое обращение» — форма, переписка с полем «Дописать» (`/api/support`). Администраторам — то же уведомление через очередь бота. Поле — как в Telegram: скрепка (картинка из галереи; приложение уменьшает её до 1600 точек, сервер хранит в `api/data/support`, показывает только автору и в админке; в Android-приложении нужен 0.7.15 — выбор файла) и стрелка.
- Ответ человеку оформлен одинаково из Telegram и из админки: «💬 Поддержка Чекера», цитатой — его последний вопрос, ниже ответ.
- Бот (`bot/relay.mjs`) отдаёт сообщение Чекеру (`/api/telegram/support`), тот сохраняет его (`support_threads`, `support_messages`). Администраторам — уведомление в Telegram: кто, начало сообщения, «Ответить в админке». Пока человек пишет подряд (паузы меньше 10 минут) и ответа нет — повторно не уведомляем. Картинку бот скачивает у Telegram и приносит Чекеру — она хранится (`api/data/support`) и видна в админке; остальные вложения (голосовое, видео, файл) бот копирует администраторам в Telegram — в базе только пометка.
- Отвечают только в админке (раздел «Поддержка», ответ уходит через `tg_outbox`): когда сообщений много, ответ «на сообщение» в Telegram легко отправить не тому. Напишет администратор боту — бот пришлёт ссылку в админку.
- Обращение: «ждёт ответа» → «отвечено» → «закрыто»; сообщение после закрытия открывает новое. Больше 30 сообщений в час от одного человека не принимаются.
- Выкладка бота — `scripts/deploy_bot.sh` (vps3), меню и описание — `--setup`.

## Важное

- Банковские данные людей в админке не показывать (сессии, операции) — только служебное: подключён ли банк, когда синхронизировался, ошибки.
- Никаких личных правил одного пользователя в общем коде.
