# Вход по отпечатку (ключи доступа, WebAuthn) — план на будущее

Статус: **отложено**. Пока хватает менеджера паролей телефона: форма входа размечена
`autocomplete="username"` / `current-password`, iOS и Android подставляют пароль после
Face ID или отпечатка без единой строки нашего кода. Ключи доступа понадобятся, когда
появятся сторонние пользователи (см. «Что дальше» в [cabinet.md](cabinet.md)).

## Зачем, если менеджер паролей уже работает

- Пароль по-прежнему существует и может утечь; ключ — нет: закрытая часть не покидает
  телефон, на сервере лежит только открытая.
- Ключ привязан к домену, поэтому поддельный сайт не выманит его, как выманивают пароль.
- Для сторонних людей это регистрация без придумывания пароля.

## Как устроено

Пароль остаётся запасным входом. Ключ добавляется к существующему пользователю.

**Создание ключа** (пользователь уже вошёл):

1. `POST /api/passkey/register/options` → сервер выдаёт одноразовый вызов (32 случайных байта)
   и параметры: `rp.id`, `user.id`, `pubKeyCredParams: [-7 (ES256), -257 (RS256)]`,
   `authenticatorSelection: { residentKey: 'required', userVerification: 'required' }`,
   `attestation: 'none'`, `excludeCredentials` — уже созданные ключи.
2. Клиент: `navigator.credentials.create({ publicKey })` — телефон спрашивает отпечаток.
3. `POST /api/passkey/register` с ответом. Сервер проверяет и сохраняет открытый ключ.

**Вход**:

1. `POST /api/passkey/login/options` → вызов, `allowCredentials` пустой: ключ «находимый»,
   логин вводить не нужно, телефон сам покажет, чей ключ.
2. Клиент: `navigator.credentials.get({ publicKey })`.
3. `POST /api/passkey/login` → сервер проверяет подпись и выдаёт обычный токен через
   `issueToken` — дальше всё как при входе по паролю.

Оба `login`-маршрута открытые, их надо поставить в `server.mjs` до проверки токена,
рядом с `/api/token`. `register`-маршруты — за проверкой.

## Сервер без зависимостей

Библиотеки (`@simplewebauthn/server`) не нужны, всё есть в `node:crypto`. Примерно 200 строк:

- **CBOR.** `attestationObject` закодирован в CBOR. Нужен разбор только малой части формата:
  целые, байтовые и текстовые строки, массивы, словари. ~60 строк.
- **clientDataJSON** — обычный JSON в base64url. Проверить: `type` (`webauthn.create` /
  `webauthn.get`), `challenge` совпадает с выданным, `origin` === наш адрес.
- **authData** — бинарная структура: `rpIdHash` (32 байта, должен быть sha256 от `rp.id`),
  флаги (UP `0x01` и UV `0x04` обязательны, AT `0x40` при создании), `signCount` (4 байта),
  при создании — `aaguid`, длина и id ключа, открытый ключ в COSE.
- **COSE → ключ.** Ключ приходит словарём COSE; перекладываем в JWK
  (`kty: 'EC', crv: 'P-256', x, y` или `kty: 'RSA', n, e`) и отдаём в
  `crypto.createPublicKey({ key: jwk, format: 'jwk' })`. Хранить удобно как SPKI DER.
- **Подпись при входе** — над `authData || sha256(clientDataJSON)`:
  `crypto.verify('sha256', data, { key, dsaEncoding: 'der' }, signature)` для ES256
  (подпись WebAuthn приходит в DER, а не в «сыром» r||s), без `dsaEncoding` для RS256.

## Таблицы

```sql
CREATE TABLE IF NOT EXISTS passkeys (
  id          TEXT PRIMARY KEY,          -- credential id, base64url
  user_id     INTEGER NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  public_key  BLOB NOT NULL,             -- SPKI DER
  alg         INTEGER NOT NULL,          -- -7 ES256 | -257 RS256
  sign_count  INTEGER NOT NULL DEFAULT 0,
  label       TEXT,                      -- «iPhone», задаётся пользователем или по aaguid
  created_at  TEXT NOT NULL,
  used_at     TEXT
);
```

Вызовы живут 5 минут и одноразовые. Один процесс — хватит `Map` в памяти; перезапуск
сервиса лишь попросит нажать кнопку ещё раз. `user.id` в WebAuthn — не логин, а случайные
байты или id пользователя: он хранится в телефоне и возвращается при входе как `userHandle`.

## Грабли, о которых стоит помнить заранее

- **Ключ намертво привязан к домену.** `rp.id = checkeris.fun`. Переезд на другой домен
  обнулит все ключи. Сейчас nginx отдаёт сайт и на `www.checkeris.fun` без редиректа —
  до ключей нужно добавить `return 301` на основной домен, иначе с `www` не совпадёт `origin`. `rp.id` и origin — в `.env` (`CHECKER_ORIGIN`), чтобы локально работал
  `localhost` (он считается безопасным контекстом).
- **Кража токена не должна превращаться в вечный доступ.** Кто украл токен, мог бы
  привязать свой ключ и входить после отзыва токена. Поэтому создание ключа требует свежего
  ввода пароля (в том же запросе или вход по паролю не старше 5 минут).
- **Смена пароля и отзыв.** `users.mjs --password` сейчас отзывает все токены; ключи
  тоже нужно показывать и уметь удалять: `users.mjs --passkeys | --revoke-passkey`, а в
  кабинете — список ключей с кнопкой удаления на случай потерянного телефона.
- **signCount.** Ключи Apple и Google, синхронизируемые через облако, присылают 0 всегда.
  Отказывать только если оба счётчика ненулевые и новый не больше старого.
- **Жест пользователя.** iOS вызывает `create`/`get` только из обработчика нажатия —
  на загрузке страницы окно не откроется. Исключение — «условный» вход:
  `mediation: 'conditional'` плюс `autocomplete="username webauthn"` на поле логина, тогда
  ключ предлагается прямо в подсказках поля. Проверять `isConditionalMediationAvailable()`.
- **Ярлык на экране.** Ключи работают и в режиме домашнего экрана (iOS 16+, Android 9+).
- **Частота попыток.** Сейчас ограничения нет ни у `/api/token`, ни будет у открытых
  `login`-маршрутов. Подбирать ключ бессмысленно, но вызовы можно выпрашивать пачками —
  ограничить оба входа заодно (например, `limit_req` в nginx на `/api/token` и `/api/passkey/`).

## Интерфейс

- Мобильная версия: на экране входа кнопка «Войти по отпечатку» (видна, если
  `window.PublicKeyCredential` есть). После входа по паролю — однократное предложение
  «Включить вход по отпечатку?»; отказ запоминается в `localStorage`.
- Кабинет: в меню пользователя — «Ключи входа»: список (метка, создан, последний вход)
  и удаление.

## Как проверить

Chrome DevTools → More tools → WebAuthn → «Enable virtual authenticator environment»:
виртуальный ключ с поддержкой resident key и user verification. Так проходятся создание,
вход, неверный origin и повтор вызова без телефона. Затем — живой iPhone и Android.
